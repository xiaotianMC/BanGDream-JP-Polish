# BanG Dream! 角色日语 TTS 优化 Skill

把 AI 翻译的中文小剧场/宣传脚本，优化成**符合 BanG Dream! 角色说话习惯、自然的日语、
并且适合 TTS 朗读**的最终台词。

## 定位

这不是翻译器，也不是角色模仿器，而是：

> **角色化日语 + 日语自然度 + TTS 可读性优化层**

输入是「中文原文 + 已有的 AI 日语翻译」，输出是可直接配音的最终台词。
核心指标不是"改得多好"，而是**改得尽可能少**——原文没问题就输出 `无需修改`。

**为什么按乐队分目录**：乐队共通的信息（语体映射、关系性、口号）集中在

## 使用

在 DSH 会话中：

- 自动触发：给出角色名 + 台词，或提到「日语优化」「角色语气」「TTS 断句」「中文优化」
- 手动触发：`/bangdream-jp-tts`

### Gate：先问目标语言，再问功能（两次调用）

> ★ **当前只开放「检查」类功能。翻译与角色化暂时隐藏**（2026-02-14 起）。

Gate 分成两步，因为**第二步的选项取决于第一步的答案**，无法一次问完。

**Gate 1 — 目标语言**（1 个问题）

| gate | id | 选项（推荐在首位） |
|---|---|---|
| **目标语言** | `target_lang` | 日语 **(推荐)** / 中文 |

**Gate 2 — 功能**（看 Gate 1 的答案再问）

选**日语**时：

| 选项（推荐在首位） | 做什么 |
|---|---|
| **両方 (推荐)** | 下面两项连着跑 |
| **基础人设检查（专有名词正确性检查）** | 专有名词表记・读音、称呼、角色语体是否与设定一致 |
| **TTS 断句及易读错字检查** | 断句・停顿・易读错字（多音字・难读字） |

选**中文**时：**只有一项**，所以选项也只有一个。

| 选项 | 做什么 |
|---|---|
| **基础人设检查（专有名词正确性检查）** | 中文表记、称呼是否与设定一致 |

选项**不带序号**（工具列表 UI 自带选择器，再写序号会重复）；
推荐项放首位并标注 `(推荐)`；每个选项都带 `description`。

**输出开头回显这两项选择**：

```
【档位】目标语言：日语 / 功能：基础人设检查（专有名词正确性检查）
```

### 两种检查各看什么

| 功能 | 走哪些 Stage | 看什么 |
|---|---|---|
| **基础人设检查** | 1 → 3 | 专有名词表记・读音 / 称呼 / 角色语体 / **有没有加出典里没有的信息**（G2） |
| **TTS 断句及易读错字检查** | 4 → 5 | 句长 / 停顿・标点 / 多音字・难读字 / **残留英字**（G9）/ 数字表记 |

**都要时先做人设检查** —— 表记一改，读音判断也跟着变。

★ **两种检查都以「指出」为主，不以「改写」为主。**
有问题就给出**根因（哪条规则・哪个词典条目）+ 建议**；
**没问题就写 `問題なし`** —— 不为了产出量去改。
判断材料不足时**不写「没问题」**，而是写「材料不足」（G8）。

### ★ 全员女性：不要把男性语当成默认（G11）

**Bandori 的乐队成员全部是女性**，但 **AI 翻译对女性角色也会产出男性语**。
这不是某个角色的问题，而是**翻译默认值的问题**，所以放在全局层（G11）。

实际被指出的例子（湊友希那）:

| 出现的 | 改成 | 问题 |
|---|---|---|
| `わたしだ。` | `わたしよ。` | 断定的自称偏男性 |
| `このあたりなんだ。` | `このあたりよ。` | `〜なんだ` 是男性说明口吻 |
| `ライブをやる。` | `ライブを行う。` | `やる` 太随意 |
| `君たち` | （删除） | **`君` 是男性对下属用的词** |
| `ただし……` | `ただ……` | 条款书面语 |
| `よろしい。` | `いいわ。` | 像老师盖章 |
| `遅れるな。` | `遅れないように。` | 命令形偏男 |
| `うん。` | `ええ。` | ★ 她几乎不说 `うん`（这条属角色层） |

**⚠️ 过剰修正同样禁止**：给常体女性角色硬加 `〜わ` / `〜のよ`、
把一人称统一成 `わたし`、把凛然语气改成 `〜ですわ` —— 都会变成别人。
**G11 是「不把男性语当默认」，不是「强制女性语尾」。**
本旨是**去掉生硬的断定**，不是加语尾。

### ★ 翻译走两遍（先自然，再复核）

**涉及「翻译」的模式（翻译成日语 / 翻译 + TTS）一律两遍**（`rules/japanese.md` J0）。

```
Pass 1  自然な初版   制約を意図的に外し、「日本人が実際にそう言うか」だけを狙う
                     （角色の語尾・称呼・TTS・句長上限を適用しない。G1/G3 は守る）
   ↓
Pass 2  規則で复核   初版に Stage 1〜6 を順に当て、1 語ずつ吟味して直す
```

**理由**：一度に全制約を満たそうとすると、**制約の数だけ日本語が硬くなる**。
先に自然さを作り、規則にそれを挑剔させる。

- **Pass 1 が既に正しければ Pass 2 は何も変えない。**
  「規則を通した証拠」として変更を作ってはいけない
- **規則が自然さを壊す場合は、勝手に選ばず【待确认】に案A/案B を並べる**
- ★ **Pass 1 の結果を出力に残す**（`【自然な初版】`）。捨てない
- **「只优化中文表达」「只做 TTS」は两遍法の対象外**——
  前者は日本語を作らないし、後者は既存の日本語を直すだけ

### 中文层的现状（尚不完善）

「只优化中文表达」需要 `characters/<角色>.zh.md`（中文层规则），**这些文件尚未建立**。

中文角色腔**只从「经历」与「性格」推导**，依据必须写在文件的 `basis` 节里、
可回溯到具体出典。禁止依据：日语语尾、对作品的泛印象、二创观感、其他作品角色。

**且该维度本身也不完整**：没有官方中文台词可依据（原作是日语），
所以推导出的中文角色腔只能是 `observed` 级别，不能当既定事实。

日语层（`characters/<band>/<角色>.md`）管 `〜だよ`／です・ます 这类语尾，
中文没有对应物，**两者不可互相套用**——否则会写出翻译腔。

## TTS 引擎

**已确定为 GPT-SoVITS**（2026-02-14）。

引擎特定行为集中在 `adapters/gpt-sovits.md`，**不写进 `rules/`**。
核心规则保持引擎无关，换引擎时只替换 adapter 文件。

**关键结果：英文一律转写为片假名（G9，无条件）。**

理由是引擎行为而非风格偏好：GPT-SoVITS 对拉丁字母走**英语 G2P**，
产出英语音素而非日语母语者说外来语时的音。`Live` → 英语 /laɪv/，不是 ライブ 的 らいぶ。
这会让角色听起来像**在说英语**，直接破坏角色还原度。

因此乐队名等英字专有名词**同样转写**：

```text
Poppin'Party  → ポッピンパーティ
BanG Dream!   → バンドリ
```

`dictionary/proper-nouns.yaml` 的 `canonical` 已同步改为片假名，
拉丁原表記保留在 `latin` 字段供追溯。转写会消掉原表記的符号（`!` `'` `*`），
**不要补回正文**。

> ⚠️ `adapters/gpt-sovits.md` 当前 `verified: false` —— 引擎行为描述基于通用架构认知，
> **尚未实机合成验证**。上机第一件事是跑其中的「验证清单」并回填结果。

**两种「verified」不是一回事。** `pronunciation.yaml` 里：

- `verified_readings` 的 `verified: true` = **朗读本身经用户确认**（该读什么）
- 其余条目的 `verified: false` = 朗读未确认
- **两者都没做 TTS 实机验证**（引擎实际发出什么音）

把前两者当成第三者会产生虚假的安心感。实机验证清单在 `adapters/gpt-sovits.md`。

**这些标记不是形式。** 用未验证的读音词典去改文本，会产生新的错误。
下一步就是把 `adapters/gpt-sovits.md` 的验证清单跑一遍——
这是目前唯一挡在可用性前面的硬问题。

## Learn 工作流：怎么让它越用越好

这是项目的长期价值所在。当你手上有「AI 原始翻译 + 人工修改版」时：

1. 把两份文本交给 skill，说明是 Learn 任务
2. skill 会逐条 diff，按 `corrections/_schema.md` 的分类归档
3. 每处改动写入 `corrections/<角色>/<日期>-<slug>.yaml`
4. **只有重复证据达到阈值才升级为规则**：
   - 1〜2 次 → `observed`（不作强制依据）
   - 3〜9 次 → `recommended`
   - 10+ 次 → `established`
5. 无法推广的改动会被**明确拒绝并记录**在 `not_promoted`

闭环：

```
人工修改 → Correction 数据集 → 规则提炼 → Skill 更新 → 下次自动修正
                    ↑                                      │
                    └──────────── 使用越多，人工修改越少 ────┘
```

### 记录质量红线

- 只有 `input`/`output` 没有 `reason` 的记录**没有价值**
- `reason` 写"更自然"等于没写
- **绝不编造对照数据**——编造的数据无法被发现，会让整个规则库失真

## 已知限制

- 不训练模型，不生成音频或情绪参数，不抓取官方台词
- 不修改历史 correction 数据（只追加）
