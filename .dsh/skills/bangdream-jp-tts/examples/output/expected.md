# 示例输出

对应 `../input/cases.md` 的四组标准答案。**以下是金标准**——如果 Skill 的输出
和这里矛盾，要么是 Skill 错了，要么是这些标准答案需要依据新证据修订
（修订要走 `../../corrections/_schema.md` 的流程）。

---

## 例 1 → 需要修改

```
【优化结果】
今日はほんっとに楽しかったー！
次も一緒にライブやろうよ！

【修改】
本当に
→ ほんっとに

すごく
→ （削除）

楽しかったです
→ 楽しかったー

やりましょう
→ やろうよ

ライブをやろうよ
→ ライブやろうよ

【原因】
- character：「本当に」的促音形「ほんっとに」是香澄兴奋时的强调形
- japanese：「ほんっとに」已承载强度，「すごく」构成程度副词重复
- character + japanese：朋友间 + 兴奋状态，です・ます 产生距离感，去掉敬体
- tts：长音「ー」辅助表现兴奋（靠词汇和表记，不靠堆符号）
- character：敬体劝诱「〜ましょう」过于客气，香澄对同辈直接邀请
- japanese：口语中助词「を」可省略

【TTS检查】
✓ 断句自然（两句均在语义边界，无需切分）
✓ 无明显多音词风险
✓ 标点适合朗读（无连续标点）
```

**注意没做的事**：没有添加「キラキラ」「みんな」等特征词——原文没有，加了就违反 G2。
这是本例最重要的"负面示范"。

## 例 2 → 无需修改

```
【优化结果】
有咲、あのギター、いくらするの？

【修改】
无需修改

【原因】
- 语义：与中文原文一致
- natural：常体，口语自然，「いくらするの？」是自然的日语问法
- character：称呼「有咲」符合香澄的称呼习惯；句尾「の？」符合她的直接提问方式
- tts：句长 13 字，无多音风险，逗号密度 2 个，适合朗读
```

**这一组是"克制"测试用例。** 如果在例 2 输出了任何改写，说明 Skill 违反了原则 5 ——
它把"优化"当成了必须产出的东西。没有缺陷就不要动。

细心的读者会注意到：这里的逗号（2 个）和「、」的使用，其实**可以**改成
「有咲、あのギターいくらするの？」。两种都自然。**没有理由的改动不做**（G3）。

## 例 3 → 需要 TTS 表记调整

```
【优化结果】
十月のライブ、三人で行こうよ！

【修改】
10月
→ 十月

3人
→ 三人

【原因】
- tts：阿拉伯数字的读法依赖引擎。「10月」可能被读作 とおつき、「3人」的助数词
  处理也不稳定。改为汉字表记规避，**语义完全不变**

【TTS检查】
✓ 断句自然
⚠ 读音：汉字表记的读法仍需确认（见下）

【待确认】
- 「十月」若被引擎读作 とおつき（而非 じゅうがつ），需要在
  dictionary/pronunciation.yaml 增加条目，或改回其他表记
- 「三人」的读法（さんにん）同样未经实际引擎验证
```

**没有做的事**：没有把「行こうよ」改掉。它在 TTS 上完全没问题，
改成别的只是为了"看起来优化过"，属于 G3 禁止的噪音修改。

## 例 4 → 全部英字转写，含专有名词（G9）

```
【优化结果】
明日はライブがあるよ！ポッピンパーティのみんなも来るよ！
ハッピーな気持ちでいっぱい！
バンドリの聖地巡礼もできるよ！

【修改】
Live
→ ライブ

Poppin'Party
→ ポッピンパーティ

Happy
→ ハッピー

BanG Dream!
→ バンドリ

【原因】
- tts + global(G9)：GPT-SoVITS はラテン文字を英語 G2P に通すため、
  `Live` は英語音素 /laɪv/ になり、日本語話者の「ライブ」にならない。
  片仮名に転写して読みを文字側で確定させる
- global(G9 専有名詞)：`Poppin'Party` も英字なので**転写対象**。
  proper-nouns.yaml の canonical は「ポッピンパーティ」に変更済み。
  G7 は写法の統一を求めるものであり、英字の保持を求めるものではない
- global(G9 符号)：`BanG Dream!` の半角 `!`、`Poppin'Party` の `'` は
  転写により消える。**本文に補わない**
- global(G7)：`BanG Dream!` の読みは公式に「バンドリ」。
  「バンドリーム」ではない

【TTS检查】
✓ 断句自然（転写後も文長は上限内）
✓ 数字・多音字のリスクなし
✓ 特殊記号（! ' *）が本文から消えた
⚠ 「ポッピンパーティ」「アヴェムジカ」等、転写後の片仮名の読みは未検証

【待确认】
- 「バンドリ」が期望の表記か要確認（公式略称。この判断は人が行う）
- 「ハッピー」の転写は日本語で実際に使われる語形を選んだ。
  機械音訳（ハッピイ等）ではない
```

**这一组的重点是"专有名词同样转写"。** 如果 Skill 保留了 `Poppin'Party` 或
`BanG Dream!`，说明它还在按**已取消的"品牌表記例外"**处理。

三个易错点：

1. **保留英字** —— 例外已取消。本项目下 `ポッピンパーティ` 就是该专有名词的统一写法。
2. **补回符号** —— 转写消掉了 `!` `'`，不要"顺手"写成「ポッピン・パーティ！」
   或「バンドリ！」。转写结果里没有原表記的符号。
3. **机械音译** —— 是 `ポッピンパーティ`（日语实际使用的读法），不是
   `ポップピンパーティ` 之类的拼读。

## 例 5 → 缺少原文，只能做内部一致性检查

```
【优化结果】
みんなとライブできて、すごく嬉しい！

【修改】
私は（削除）

みんなと一緒に
→ みんなと

〜することができて
→ 〜できて

とても
→ すごく

【原因】
- japanese：「私は」是中文式主语冗余，日语口语中已知主语通常省略
- japanese：「みんなと一緒に」中「一緒に」冗余（「と」已表共同）
- japanese：形式名词 + する 的复合结构「〜することができて」在口语中缩为「〜できて」
- japanese：「とても」偏书面，口语用「すごく」

【TTS检查】
✓ 断句自然（「、」处为从句边界，位置正确）
✓ 无明显多音词风险
✓ 标点适合朗读

【待确认】
⚠ 本组**未提供中文原文**，因此 Stage 1（翻译检查）只做了内部一致性检查，
   无法确认语义是否与原文一致。修改仅基于日语句内问题。
   若有原文请补充，以便复核「ライブできて」的语义是否完整对应。
```

**这一组测试的是诚实性。** 缺少原文时，Skill 必须说明它没有做语义检查，
而不是默认语义正确、也不是假装检查过。这是 G8 的直接应用。

另外注意：本例**没有**改写「嬉しい」为「めっちゃ嬉しい」或加「ほんっとに」。
因为没有场景信息，无法判断情绪强度——**不确定时保守**。
