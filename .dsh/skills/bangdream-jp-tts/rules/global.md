# Global 规则

适用于所有角色、所有场景。这一层优先级最高，**任何角色规则都不能违反它**。

违反 Global 的修改一律作废，哪怕它让句子更角色化、更好读。

---

## G1 不改变原始语义

优化后的日语，其**信息内容**必须与中文原文一致。

判断标准：把优化后的日语回译成中文，除了口语化程度和语气之外，不应有任何信息差异。

禁止：

- 把陈述改成疑问，把疑问改成陈述
- 增删因果、条件、时间关系
- 把"可能"说成"确定"，把"讨厌"说成"不太喜欢"
- 把主语/宾语搞混（日语省略主语时尤其容易出错）

---

## G2 不擅自添加信息

原文没有的，不要加。特别是：

- **不要补设定**。原文没提乐队、没提某个人，就不要为了"更 BanG Dream"而塞进去。
- **不要补情绪理由**。"楽しかった" 后面不要自动接 "みんなと一緒だったから"。
- **不要补语气词之外的词汇**。语气词（ね/よ/さ/な）通常是允许的，它属于语气而非信息。
- **不要补称呼**。原文没叫对方名字，就不要加。

**例外**：原文是中文、且中文本身省略了日语中必须显性化的成分（如授受关系、敬语体），此时补出的是语法必需成分，不算添加信息。这类补充要在 `【原因】` 里说明。

---

## G3 不过度润色

不需要修改的地方不要动。

- 已经自然的表达，保留。
- 同义改写不是优化。把「とても」换成「すごく」而不说明理由，属于噪音修改。
- 不要为了"看起来认真改过了"而制造改动。
- 一次修改能解决的，不要拆成三次。

---

## G4 不把口语全部改成书面语

反向也成立：**不要把所有口语都当成错误**。

- 「〜です・ます」本身不是错误。角色在正式场合、对长辈、营业状态说话时，です・ます 是**正确**的。
- 不要机械去敬语化。判断依据是角色设定 + 场景，不是"口语比书面语好"。
- 详见 `japanese.md` J1——那一节讲的是"该口语的地方用了书面语"，不是"书面语一律要改"。

---

## G5 不为了 TTS 过度增加标点

TTS 优化是最后一层，不能反过来破坏文本。

- 不要为了让 TTS 停顿而把一句话切成四段。
- 不要滥用「、」。日语逗号密度过高会让 TTS 变得断断续续、失去流畅感。
- 不要加原文没有的「……」。省略号是语义工具（犹豫、无语、余韵），不是停顿工具。
- 换行只在真实存在语句边界时使用。

详见 `tts.md` T1/T2。

---

## G6 保持人物关系正确

称呼和敬语体现人物关系，是信息的一部分。

- **称呼一致**：同一场景内，A 怎么称呼 B 必须稳定。香澄叫「有咲」就不能下一句变成「市ヶ谷さん」。
- **敬语等级反映关系**：后辈对前辈、学生对老师、初次见面的人，敬语等级不能因为"角色平时说话随意"就整个抹掉。
- **关系变化要跟随**：如果剧情里关系变了（刚认识 → 熟悉），敬语等级的变化是**正确的**，不要当作不自然去"修正"。
- **三态区分**：多形态称呼分两种性质——`progression: true`（关系推进的时间序列）
  与 `false`（同时可用的变体）。前者阶段用错就是错，后者择一即可。
  字段定义见 `../dictionary/address-forms.yaml`。
- 角色之间的称呼对应表见 `../dictionary/address-forms.yaml`（称呼的唯一事实来源）。

---

## G7 保持专有名词一致

- 乐队名、角色名、曲名、地名一律查 `../dictionary/proper-nouns.yaml`，**不得自行音译或改写**。
- 同一个专有名词在整个项目内必须只有一种写法。
- 若发现词典里没有的专有名词：**不要猜**。在 `【待确认】` 中列出，并建议新增词典条目。
- 首次出现的专有名词，考虑是否需要读音标注（见 `tts.md` T3）。

---

## G8 不确定就说不确定

- 中文原文缺失时，不要脑补原文去判断语义是否正确——明确说明只能做内部一致性检查。
- 读音、断句依赖具体 TTS 引擎时，写进 `【待确认】`，不要静默二选一。
- 场景/情绪靠推断时，说明推断依据。
- **静默猜测是本 Skill 最严重的失败模式**，比改错更糟，因为它不可被发现。

---

## G9 英文一律转写为假名（日式英语）

文本中出现的英文（拉丁字母），**一律转写成片假名，无例外**。

理由属 TTS 层，且已确定引擎为 **GPT-SoVITS**，因此这条理由从"可能性"变成"已知行为"：

- GPT-SoVITS 对拉丁字母走**英语 G2P** 通路，产出的是**英语音素**，而不是日语母语者
  说外来语时的音。`Live` → 英语 /laɪv/，而不是 ライブ 的 らいぶ。
- 对一个说日语的 BanG Dream 角色来说，这会让角色听起来像**在说英语**，直接破坏
  角色还原度。
- 引擎遇到拉丁字母时的其他可能行为（逐字母读成 `エル・アイ・ヴィー・イー`、
  或直接跳过）同样是硬错误。

转成片假名后，读音由**字符本身确定**，不再依赖引擎的语言判定。这是本规则的目的。

```text
❌ 今日は Live があるよ！
✅ 今日はライブがあるよ！
```

> 引擎细节与实测方法见 `../adapters/gpt-sovits.md`。

### 转写对照

| 英文 | 片假名 | 备注 |
|---|---|---|
| Live | ライブ | |
| Happy | ハッピー | |
| Hello | ハロー | |
| Camera | カメラ | |
| Smartphone / Phone | スマホ / フォン | |
| Dream | ドリーム | |
| Music | ミュージック | |
| Guitar | ギター | |
| Stage | ステージ | |
| Live House | ライブハウス | |

**注意**：「スマホ」是「スマートフォン」的略称，不是「Smartphone」的音译。转写目标是
**日语中实际使用的那个词**，不是机械音译。转写前先确认：日本人平时怎么说这个词？

### 专有名词也要转写

**这是本条规则最关键的部分。** 乐队名、作品名的英字表記**同样转写**：

```text
Poppin'Party     → ポッピンパーティ
Roselia          → ロゼリア
Afterglow        → アフターグロウ
Pastel*Palettes  → パステルパレット
Morfonica        → モルフォニカ
RAISE A SUILEN   → レイズアスイレン
MyGO!!!!!        → マイゴ
Ave Mujica       → アヴェムジカ
BanG Dream!      → バンドリ
```

**为什么不违反 G7？** G7 要求专有名词**写法统一**，不要求保留拉丁字母。
在本项目下，`ポッピンパーティ` 就是该专有名词的统一写法——
`../dictionary/proper-nouns.yaml` 的 `canonical` 已同步改为片假名，
拉丁原表記保留在同条目的 `latin` 字段供追溯。

**符号随地处理**：转写会消掉原表記里的符号（`'` `*` `!`），这正是我们要的——
GPT-SoVITS 对这类符号处理不可预测。

```text
MyGO!!!!!  → マイゴ        （「！」は持ち込まない）
BanG Dream!→ バンドリ      （半角「!」は消える）
```

### 例外（仅限下面 3 类，不涉及专有名词）

1. **读者可见的标识符** —— 型号、URL、ID、代码、语言标记。
   ```text
   ISBN 978-4-... / https://... / track_01 / ja-JP
   ```
   这类不转写，或按原文要求处理。**注意**：缩写（`BD` `TGS` `OP`）**属于转写对象**，
   不要归到这一类——`BD` → `ビーディー`、`OP` → `オープニング`。

2. **不朗读的文本** —— 制作备注、舞台指示、staff 记事的英文。
   **只转写会被朗读的正文。**

3. **原文已是假名的外来语** —— 不要反向改写，也不要重写。
   ```text
   ライブ → ライブ   （保持，不要改成 Live，也不要改成 ライヴ）
   ```

### 与既有规则的关系

- **G2 不冲突**：转写是**表记层**改动，语义与信息量不变，不属于"添加信息"。
- **G3 不冲突**：这不是"为改而改"——只有当正文存在拉丁字母时才触发；原本没有拉丁字母的
  文本不受本规则影响。
- **G7 不冲突**：见上「专有名词也要转写」。G7 管写法统一，G9 决定**统一成哪种写法**；
  两者由 `proper-nouns.yaml` 的 `canonical` 保持同步。
- **与 J3 的分工**：G9 管"英文该不该转写"，J3 管"标点用得对不对"。转写后残留的标点
  按 J3 处理，但**不要补回原表記的符号**。

### 不做的事

- ❌ 不要机械音译，要转写成日语中实际使用的那个词
- ❌ 不要转写不朗读的文本
- ❌ 不要反向改写（假名 → 英文），也不要改写既有假名表记
- ❌ **不要把原表記的符号（`!` `*` `'`）转写后补回正文**
- ❌ 不要因为"这是品牌名"就保留英字——本项目已决定一律转写

### 转写后要检查什么

1. **句子长度会变。** 部分词变长（`Music` 5 字 → `ミュージック` 6 字，
   `Smartphone` 10 字 → スマートフォン 7 字），部分变短（`Live` → ライブ 3 字）。
   **转写后重新过一遍 Stage 4 断句**（`tts.md` T1）——转写可能让原本合规的句子超长。

2. **同形异义。** 转写后的片假名若与上下文中已有词同形，可能产生歧义。这属 G1 风险，
   需要确认后使用。

3. **读音仍需验证。** 转写只是**提高**读音可控性，不等于已验证。片假名本身也可能读错
   （尤其含「ヴ」的 アヴェムジカ）。未验证的写入 `【待确认】`，
   不要假定转写就万事大吉。

### 适用范围

- 本规则作用于**文本层**，不做任何引擎控制语法（见 SKILL.md「Engine independence」）。
- 引擎特定行为见 `../adapters/gpt-sovits.md`。换引擎时本规则可能需重新评估——
  例如某引擎能稳定按日语读英字，则转写的必要性下降，但**读法确定性**仍然支持转写。
- `../dictionary/proper-nouns.yaml` 的 `canonical` 是转写结果的**唯一事实来源**。
  词典里没有的英文专有名词**不要猜**（G7/G8），列入 `【待确认】` 并建议新增词典条目。

## G10 引用原始资料前，先看它是不是「本篇内容」

角色知识来自萌娘百科等**二手资料**。这些页面里混着**不是作品本篇的文字**，
最典型的是两种：

| 标记 | 含义 | 处理 |
|---|---|---|
| `just-kidding-text`（删除线玩笑） | 编者**自己标注为玩笑/玩梗** | ★★ **不得作为台词的依据** |
| `heimu`（黑幕，鼠标悬停才显示） | 隐藏文本。**推测、补充、剧透**居多 | ★ 引用前确认它是**资料原文还是编者推测** |

**为什么单独立一条**：这两种文字在纯文本化之后**和地之文连在一起**，
看不出边界。曾经因此把一句玩笑当作角色台词引用，并据此写了例句 ——
这正是 G8 说的「静默猜测」，而且**更隐蔽，因为它看起来有出处**。

```text
❌ 把 <s class="just-kidding-text"> 里的句子当角色台词引用
❌ 把 heimu（黑幕）里的推测当设定写入角色文件
✅ 引用前确认该句是否被标注为玩笑／推测
✅ 是推测就标「出典自身が推测と明示」；是玩笑就排除
```

**工具层面的对策**：仓库根的 `extract.mjs` 已把这两种标记**显式转成
`〖冗談〗…〖/冗談〗` / `〖伏せ字〗…〖/伏せ字〗`**。
抽出的文本里出现这些标记时，**必须先判断再引用**。

### 附带注意：`轶事` 节比 `经历` 节更容易含玩笑

- **`经历`（经历）节** —— 事实记述が中心。**角色文件にはこちらを優先**
- **`轶事`（轶事）节** —— ネタ・愛称・視聴者の推測が中心。**出典の明示を確認してから**

### 粉丝推测不得写入设定

出典自身が「**假药**」「**推测**」「**扑朔迷离**」と明示している節
（例：`若葉睦` の「关于姐妹的推测」）は、
**角色ファイルに设定として書いてはいけない**。
「そのような推测が存在する」と**記録するに留める**。

## G11 登場人物は全員女性 —— 男性語を既定にしない

**ユーザー指定（2026-02-14）**：
*「为减少语气生硬，补全所有乐队成员均为女性」*

**BanG Dream! のバンド成員は全員女性である。**
→ **翻訳の既定は「女性が話す日本語」**。
**一人称・語尾・命令形・呼びかけが男性語に寄っていたら直す。**

### なぜ独立した規則にするか

**AI 翻訳は、女性角色に対しても男性語を出す傾向がある。**
これは**個別の角色の問題ではなく、翻訳の既定値の問題**である。
→ 角色ファイルごとに直すのではなく、**全モード・全角色に効く層**に置く。

ユーザーが実際に受けた指摘（湊友希那の成稿より）：

| 出た | 直した | 何が問題か |
|---|---|---|
| `わたしだ。` | `わたしよ。` | **断定 `〜だ` が男性的に硬い**。名乗りで特に目立つ |
| `このあたりなんだ。` | `このあたりよ。` | **`〜なんだ` は男性の説明口調**。女性の説明は `〜のよ` `〜の` |
| `ライブをやる。` | `ライブを行う。` | **`やる` が雑で男性的**。改まった場面では `行う` |
| `君たち` | （削除） | **`君` は男性が目下へ使う語**。女性はまず使わない |
| `ただし……` | `ただ……` | **`ただし` は条文・規約の書き言葉**。話し言葉では `ただ` |
| `よろしい。` | `いいわ。` | **`よろしい` は目上・教師が許可を出す響き**。若い女性の日常会話では硬すぎる |
| `遅れるな。` | `遅れないように。` | **命令形 `〜な` は男性の命令**。女性は `〜ないように` `〜してね` |
| `うん。`（2 箇所） | `ええ。` | **この角色は `うん` をほとんど言わない**（⇒ 角色層。下記） |

### 直す対象（男性語に寄る典型）

```text
❌ 一人称：僕 / 俺 / わたしだ（断定形の名乗り）
❌ 命令形：〜しろ / 〜しなさい（強）/ 〜するな
❌ 男性的な依頼・勧誘：〜しようぜ / 〜してくれ / 〜してくれよ
❌ 呼びかけ：君 / 君たち / お前 / 〜よ（呼びかけの「よ」）
❌ 男性的な終助詞：〜だぜ / 〜だぞ / 〜かい / 〜だな（独白）
❌ 硬い断定：〜である / 〜だ（名乗り・説明での連発）
❌ 書き言葉の接続：ただし / なお / ゆえに（話し言葉では ただ / それと）
❌ 過度に改まった許可・評価：よろしい / 〜であるな
```

### ★ 直す対象**ではない**もの（過剰修正しない）

**女性語尾を機械的に足すのも同じくらい悪い。**

```text
❌ 常体の女性角色に、無理に 〜わ / 〜のよ / 〜かしら を足す
   → 后述のとおり、`〜わ` は若い女性の自然会話ではむしろ古風・演劇的
❌ 一人称を全員 `わたし` に統一する
   → 角色ごとに違う（`わたくし` / `アタシ` / `私`）。G7 と同じく角色設定が優先
❌ 凛とした語調を `〜ですわ` に変える
   → 角色が別人になる
```

### 角色ごとの扱い（優先順位）

**G11 は「男性語を既定にしない」規則であって、「女性語尾を強制する」規則ではない。**

```
1. characters/<角色>.md に語尾・一人称の記載があれば → それが最優先
2. 記載が無い場合 → 自然な日本語の範囲で、男性語に寄らない形を選ぶ
3. それでも `〜だ` が硬いと感じたら → 柔らかい等価形を検討する（下記）
```

**角色ごとの実際の違い**：

| 角色 | 語尾 | 注意 |
|---|---|---|
| 湊友希那 | **凛とした常体** | ★ `〜だ` の連発を避ける。`〜よ` `〜の` も混ぜる。**`君` を使わない** |
| 長崎そよ | 二層（外向き丁寧 / 内向き常体） | `〜わ` `〜のよ` は**使わない**（自然さ優先） |
| 椎名立希 | 常体 + 男性的な力強さ | ★ `〜だぜ` `〜しろ` は **G11 違反**。`〜だ` `〜よ` で強さを出す |
| 八幡海鈴 | 丁寧体（立希には常体） | `〜わ` 等は付けない |
| 珠手知由 | 尊大な常体 | `〜わよ` は**自然に合う**（出典の性格根拠あり） |

> ★ **`〜わ` の扱いに注意。**
> 若い女性の自然会話では、**`〜わ` は古風・演劇的に響く**ことがある
> （特に東京方言の若年層）。**必ずしも女性らしさの正解ではない**。
> 角色が**尊大・お嬢様・演劇的**な場合（知由、祥子など）には合う。
> **「女性だから `〜わ`」と自動変換しない。**

### 「硬さ」を減らす方向（ユーザー指摘の本旨）

ユーザーの意図は**「語尾を女性化する」より「硬さを減らす」**。
→ **断定を柔らげる**のが主眼：

```text
わたしだ。        → わたしよ。        （名乗りの断定を避ける）
このあたりなんだ。 → このあたりよ。     （男性の説明口調を避ける）
遅れるな。        → 遅れないように。   （命令形を依頼形へ）
ただし……         → ただ……           （書き言葉を話し言葉へ）
よろしい。        → いいわ。          （過剰な権威を外す）
```

★ **`〜わ` を足すのではなく、硬い断定を外す**のが中心の作業。
**過剰修正の検出**：直した結果が
**「角色が別人になった」**と感じられるなら、直しすぎ。

### 角色層の逐語ルール（`うん` → `ええ` など）

**特定の角色が特定の語をほとんど使わない**場合は、**角色層に書く**（G11 ではない）。

例：**湊友希那は `うん` をほとんど言わない → `ええ` を使う**
（ユーザー指摘）。これは `characters/roselia/yukina.md` の担当。

> **切り分け**：
> - **「女性だから男性語を避ける」** → G11（全角色共通）
> - **「この角色はこの語を使わない」** → 角色ファイル
