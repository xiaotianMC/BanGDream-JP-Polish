# Global 规则

适用于所有角色、所有场景。这一层优先级最高，**任何角色规则都不能违反它**。

违反 Global 的修改一律作废，哪怕它让句子更角色化、更好读。

---

## G1 不改变原始语义

优化后的日语，其**信息内容**必须与中文原文一致。

判断标准：把优化后的日语回译成中文，除了口语化程度和语气之外，不应有任何信息差异。

禁止：

- 把陈述改成疑问，把疑问改成陈述
- 增删因果、条件、时间关系
- 把"可能"说成"确定"，把"讨厌"说成"不太喜欢"
- 把主语/宾语搞混（日语省略主语时尤其容易出错）

---

## G2 不擅自添加信息

原文没有的，不要加。特别是：

- **不要补设定**。原文没提乐队、没提某个人，就不要为了"更 BanG Dream"而塞进去。
- **不要补情绪理由**。"楽しかった" 后面不要自动接 "みんなと一緒だったから"。
- **不要补语气词之外的词汇**。语气词（ね/よ/さ/な）通常是允许的，它属于语气而非信息。
- **不要补称呼**。原文没叫对方名字，就不要加。

**例外**：原文是中文、且中文本身省略了日语中必须显性化的成分（如授受关系、敬语体），此时补出的是语法必需成分，不算添加信息。这类补充要在 `【原因】` 里说明。

---

## G3 不过度润色

不需要修改的地方不要动。

- 已经自然的表达，保留。
- 同义改写不是优化。把「とても」换成「すごく」而不说明理由，属于噪音修改。
- 不要为了"看起来认真改过了"而制造改动。
- 一次修改能解决的，不要拆成三次。

---

## G4 不把口语全部改成书面语

反向也成立：**不要把所有口语都当成错误**。

- 「〜です・ます」本身不是错误。角色在正式场合、对长辈、营业状态说话时，です・ます 是**正确**的。
- 不要机械去敬语化。判断依据是角色设定 + 场景，不是"口语比书面语好"。
- 详见 `japanese.md` J1——那一节讲的是"该口语的地方用了书面语"，不是"书面语一律要改"。

---

## G5 不为了 TTS 过度增加标点

TTS 优化是最后一层，不能反过来破坏文本。

- 不要为了让 TTS 停顿而把一句话切成四段。
- 不要滥用「、」。日语逗号密度过高会让 TTS 变得断断续续、失去流畅感。
- 不要加原文没有的「……」。省略号是语义工具（犹豫、无语、余韵），不是停顿工具。
- 换行只在真实存在语句边界时使用。

详见 `tts.md` T1/T2。

---

## G6 保持人物关系正确

称呼和敬语体现人物关系，是信息的一部分。

- **称呼一致**：同一场景内，A 怎么称呼 B 必须稳定。香澄叫「有咲」就不能下一句变成「市ヶ谷さん」。
- **敬语等级反映关系**：后辈对前辈、学生对老师、初次见面的人，敬语等级不能因为"角色平时说话随意"就整个抹掉。
- **关系变化要跟随**：如果剧情里关系变了（刚认识 → 熟悉），敬语等级的变化是**正确的**，不要当作不自然去"修正"。
- 角色之间的称呼对应表见 `../dictionary/proper-nouns.yaml` 的 `address_forms`。

---

## G7 保持专有名词一致

- 乐队名、角色名、曲名、地名一律查 `../dictionary/proper-nouns.yaml`，**不得自行音译或改写**。
- 同一个专有名词在整个项目内必须只有一种写法。
- 若发现词典里没有的专有名词：**不要猜**。在 `【待确认】` 中列出，并建议新增词典条目。
- 首次出现的专有名词，考虑是否需要读音标注（见 `tts.md` T3）。

---

## G8 不确定就说不确定

- 中文原文缺失时，不要脑补原文去判断语义是否正确——明确说明只能做内部一致性检查。
- 读音、断句依赖具体 TTS 引擎时，写进 `【待确认】`，不要静默二选一。
- 场景/情绪靠推断时，说明推断依据。
- **静默猜测是本 Skill 最严重的失败模式**，比改错更糟，因为它不可被发现。

---

## G9 英文默认转写为假名（日式英语）

文本中出现的英文（拉丁字母），**默认转写成片假名**。

理由属 TTS 层：引擎遇到拉丁字母时行为不可控——可能逐字母读（`Live` → エル・アイ・ヴィー・イー）、
可能按英文单词读、也可能跳过。转成片假名可以锁定读音，这是本规则的核心目的。

```text
❌ 今日は Live があるよ！
✅ 今日はライブがあるよ！
```

### 转写对照

| 英文 | 片假名 | 备注 |
|---|---|---|
| Live | ライブ | |
| Happy | ハッピー | |
| Hello | ハロー | |
| Camera | カメラ | |
| Smartphone / Phone | スマホ / フォン | |
| Dream | ドリーム | |
| Music | ミュージック | |
| Guitar | ギター | |
| Stage | ステージ | |
| Live House | ライブハウス | |

**注意**：「スマホ」是「スマートフォン」的略称，不是「Smartphone」的音译。转写目标是
**日语中实际使用的那个词**，不是机械音译。转写前先确认：日本人平时怎么说这个词？

### 例外（优先级从高到低）

1. **专有名词的公式表記** —— 最高优先。凡 `../dictionary/proper-nouns.yaml` 中标注
   「公式表記は英語」「表記は英語」的条目，**保留英文原样，不转写**。
   ```text
   乐队名：Poppin'Party / Roselia / Afterglow / Pastel*Palettes
           RAISE A SUILEN / Morfonica / Ave Mujica / MyGO!!!!!
   作品名：BanG Dream!
   ```
   这些不是普通英文单词，而是品牌表記。改成片假名属改变专有名词，违反 G7。
   读音由 TTS 词典或引擎的专有名词处理负责，**不由改写正文负责**。

2. **`../dictionary/pronunciation.yaml` 中已登记的英字条目** —— 按词典的 `reading` 处理，
   不按本文的默认音译。

3. **读者可见的标识符** —— 缩写、型号、URL、ID、代码、语言标记。
   ```text
   BD / TGS / OP / ISBN / https://... / track_01
   ```
   这类不转写，或按词典 / 原文要求处理。

4. **不朗读的文本** —— 制作备注、舞台指示、staff 记事的英文。**只转写会被朗读的正文**。

5. **原文本已是假名的外来语** —— 不要反向改写，也不要重写。
   ```text
   ライブ → ライブ   （保持，不要改成 Live，也不要改成ライヴ）
   ```

### 与既有规则的关系

- **G2 不冲突**：转写是**表记层**改动，语义与信息量不变，不属于"添加信息"。
- **G3 不冲突**：这不是"为改而改"——只有当正文存在拉丁字母时才触发；原本没有拉丁字母的
  文本不受本规则影响。
- **优先于标点统一**：`BanG Dream!` 的半角 `!` 不改成全角 `！`（见例外 1）。
- **与 J3 的分工**：G9 管"英文该不该转写"，J3 管"标点用得对不对"。

### 不做的事

- ❌ 不要把**已在词典中的公式表記**转成片假名
- ❌ 不要机械音译，要转写成日语中实际使用的那个词
- ❌ 不要转写不朗读的文本
- ❌ 不要反向改写（假名 → 英文），也不要改写既有假名表记
- ❌ 转写后不要改变句子长度结构（见下）

### 转写后要检查什么

1. **句子变长了。** 片假名通常比英文原词长（`Live` 4 字 → `ライブ` 3 字，
   但 `Smartphone` 10 字 → `スマートフォン` 7 字，`Happy` 5 字 → `ハッピー` 4 字；
   部分词会变长，如 `Music` 5 字 → `ミュージック` 6 字）。
   **转写后重新过一遍 Stage 4 断句**（`tts.md` T1）——转写可能让原本合规的句子超长。

2. **同形异义。** 转写后的片假名若与上下文中已有词同形，可能产生歧义。这属 G1 风险，
   需要确认后使用。

3. **读音仍需验证。** 转写只是**提高**读音可控性，不等于已验证。
   引擎是否按预期读该片假名，仍要实际听过。未验证的写入 `【待确认】`，
   不要假定转写就万事大吉。

### 适用范围

- 本规则作用于**文本层**，不做任何引擎控制语法（见 SKILL.md「Engine independence」）。
- 当 TTS 引擎未确定时，拉丁字母的读音风险按 `tts.md` T3 作为**已确定风险**处理，
  而不是挂起等引擎——因为无论哪个引擎，逐字母读的可能性都真实存在。
- `../dictionary/proper-nouns.yaml` 是例外 1 的**唯一事实来源**。词典里没有的英文专有名词
  **不要猜**（G7/G8），列入 `【待确认】` 并建议新增词典条目。
