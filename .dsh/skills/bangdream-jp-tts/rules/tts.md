# TTS 规则

TTS 可读性层。**优先级最低**，不能破坏角色语言（Global G5 / 原则 4）。

唯一例外：**读音层可以否决角色层**（T5 的 veto 机制）。这是因为误读是硬错误，而表达方式通常有多个等价选择。

---

## T1 断句

### 判断句长

日语 TTS 一句的自然上限大约 **20〜30 字（モーラ 计约 30〜40）**。超过后：

- 呼吸点缺失，听感疲惫
- 语调无法维持，后半句塌下来
- 情绪表达被稀释

**但不是每句都要切。** 短句本来就多，长句才需要处理。

### 切分位置

在**语义边界**切，不在字数中点切：

```text
今日はみんなと一緒にライブができて本当に嬉しいです！
```

切法 A（正确——在从句/主题边界）：
```text
今日はみんなと一緒にライブができて、
ほんっとに嬉しい！
```

切法 B（错误——把修饰语和中心词切开）：
```text
今日はみんなと一緒にライブが、
できて本当に嬉しいです！
```

**禁止切分点**：

- 修饰语与其被修饰名词之间（「白い、ギター」）
- 动词与其补语之间（「ライブを、する」）
- 复合名词内部（「文化、祭」）
- て 形连接的两个动作若语义上是一个整体（「行って、みる」）

**推荐切分点**：

- 「て」形从句结束处
- 条件/原因从句结束处（〜から、〜ので、〜たら、〜なら）
- 主题提示之后（〜は、〜って）
- 时间状语之后
- 引用助词「と」+ 言う 之间（视情况）

### 切分方式的选择

在同一个位置，可以：

| 方式 | 效果 | 何时用 |
|---|---|---|
| 加 `、` | 短停顿，同句内 | 从句边界，语义连贯 |
| 换行 | 较长停顿，视为另一句 | 完整句边界 |
| 保留不切 | — | 句子虽长但语义不可分 |

**换行的代价**：多数引擎把换行当作句子边界，语调和音高会重置，情绪连贯性下降。所以换行要慎用，优先用 `、`。

## T2 停顿

### 符号 → 停顿长度（相对值）

这是通用倾向，**具体引擎行为不同**——不要把它当绝对值写进文本处理逻辑。

```text
。（句末）      ████████  最长，语调收束
！              ███████   视引擎，可能较长或很短（爆发）
？              ███████   上升语调收束
……             ██████    拖长，常带气息感
、              ███       短停顿
换行            ████████  句边界重置
无标点连续假名  █         基本不停
```

### 让停顿服务表达

```text
（犹豫）
えっと、その……うん、そうだね。
```
→ `、` 与 `……` 交替，制造断续感。

```text
（一口气说完，兴奋）
やばいやばいやばい！超楽しかった！
```
→ 第一句刻意不放逗号，形成连珠效果。

**不要为了停顿而加符号**（G5）。停顿是结果，不是目的。先确定这句话该怎么被说出来，再选符号。

### 逗号密度上限

经验值：**一句内 `、` 不超过 2〜3 个**。超过后 TTS 会变成断断续续的朗读，失去语句感。

## T3 读音

### 高风险类别

按出错概率排序：

| 类别 | 例 | 风险 |
|---|---|---|
| 人名（尤其当用汉字） | 戸山香澄、市ヶ谷有咲、湊友希那 | 高——几乎必然误读 |
| 难读地名 | 小豆島、安房鴨川、逗子 | 高——圣地向脚本必查 |
| 多音汉字 | 生、行、空、人、日、下 | 高 |
| 英字（拉丁字母） | Live、Happy、Poppin'Party | 高——**已确定引擎下走英语 G2P**，产出英语音素。一律转写，见 `global.md` G9 |
| 缩写（英字） | BD、TGS、OP | 高——转写为片假名（`ビーディー` 等），见 G9 |
| 数字 | 3人、10月、1つ | 中——读法依赖上下文 |
| 特殊符号 | 〜、×、☆、`*`、`'` | 高——可能被读成符号名。转写会顺带消除多数 |
| 外来语（片假名） | ギター、ライブ、ステージ | 低——字符与读音近乎一一对应 |

### 处理手段（按优先级）

1. **查词典**：`../dictionary/pronunciation.yaml`
2. **查专有名词表**：`../dictionary/proper-nouns.yaml`
3. **改写规避**：如果该词有等价表达，换一个
   - `3人` → `三人（さんにん）` 或 `みんな`
   - `10月` → `十月（じゅうがつ）`
4. **假名注记**：在文本中直接写假名（最可靠，但可能影响其他环节）
5. **记入 `【待确认】`**：当读法依赖引擎、或词典缺失时

### 何时用假名

- **人名首次出现且引擎易错** → 用假名或加词典
- **角色本身就说错/故意用特殊读法** → 保留，记入词典并注明
- **专有名词统一性优先** → 见 G7

**不要**把整句改成假名。这会破坏文本可读性和其他处理环节。

## T4 情绪

**本 Skill 不生成语音情绪参数。** 只通过文本手段辅助 TTS 表达。

### 可用手段

| 手段 | 效果 | 例 |
|---|---|---|
| 标点 | `！` 强调，`？` 上扬，`……` 拖长 | `すごい！` |
| 句式 | 短句断裂 → 兴奋；长句 → 平静 | `やばい！やばい！` |
| 语气词 | 句末助词定调 | `〜だよ`（告知）/ `〜だね`（共感） |
| 重复 | 单词或短语重复 → 情绪高扬 | `すごいすごい！` |
| 长音 | `ー` 延长 → 兴奋、拖腔 | `楽しかったー！` |
| 停顿 | 断续 → 犹豫；连贯 → 流畅 | `えっと、その……` |
| 促音 | 小 `っ` 插入 → 强调、急切 | `ほんっとに` |
| 拨音 | `ん` 插入 → 口语化、随意 | `そうなんだ` |

### 情绪对照

| 情绪 | 文本特征 |
|---|---|
| 兴奋 | 短句、`！`、重复、长音、促音 |
| 惊讶 | 短促、`！`/`？`、`えっ`、`まじで` |
| 害羞 | 省略、`……`、句末含糊（`〜かな`、`〜けど`）、音量感低 |
| 悲伤 | 长句、`……`、句末弱化、少 `！` |
| 生气 | 短句、断句硬、`！`、无语气词（去 `ね` 是重要信号） |
| 疑问 | `？`、上升句末、`の`/`の？` |
| 犹豫 | `……`、`、` 交替、`えっと`/`その`、句末不结 |
| 吐槽 | 短、干、`……`、`いや`、`って`、常带 `。` 收尾 |

### 关键约束

- **情绪手段不能违反正文章节**。香澄的「〜だよ」不能加到友希那的台词上。
- **不要为了情绪而堆符号**。`！！！` 或「すごい！すごい！すごい！」三连是很弱的写法，且引擎可能读得机械。
- **情绪靠词汇和句式，不靠符号数量**。这是本层的核心判断。
- 具体的角色情绪表达方式见 `../characters/<角色>.md` 的 `emotional_style`。

## T5 读音 veto（唯一的层级覆盖）

当读音问题严重时，TTS 层可以把决定**退回**给角色层重新选词：

### 触发条件（必须同时满足）

1. 该词是**硬错误**——TTS 必然读错，不是"可能读错"
2. 词典无法解决（无法新增条目，或新增后仍不可靠）
3. 存在**语义等价的替代表达**

### 处理方式

```text
【待确认】「◯◯」读音风险高，已改写为「△△」。
原因：tts
→ 建议由角色层确认「△△」是否符合角色口吻。
```

### 边界（不能做的事）

- ❌ 因为是长句就删掉角色特征词
- ❌ 因为逗号会导致停顿就删掉角色语气词
- ❌ 因为某表达 TTS 处理不好就换成书面语
- ❌ 以"TTS 友好"为名做任何未经确认的语义替换

**能绕过角色层的只有"必然误读"这一种情况。** 其他所有 TTS 问题都只能提建议，不能单方面改。

## T6 检查清单

- [ ] 有无超长句（>30 字）需要断句
- [ ] 切分点是否在语义边界（没切开修饰语/补语/复合名词）
- [ ] `、` 密度是否 ≤ 2〜3 / 句
- [ ] 换行是否只用在真正的句边界
- [ ] 连续标点（`！！`、`？。`）是否清除
- [ ] 所有专有名词是否在词典中且读音一致
- [ ] 多音字、数字、缩写、英文是否处理
- [ ] 情绪是否有文本手段支撑（且未靠堆符号）
- [ ] 所有未解决的读音/停顿问题是否写入 `【待确认】`
- [ ] 若动用了 T5 veto，是否满足三个触发条件
