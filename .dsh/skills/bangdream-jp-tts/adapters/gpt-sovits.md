## 架构要点（影响文本处理的部分）

GPT-SoVITS 是「文本前端 + 声学模型」两段式。文本侧的链路大致是：

```text
输入文本
  ↓ 语言判定 / 切分
  ↓ 按语言分别做前端处理
  ↓   · 日语：分词 → 读音（音素）
  ↓   · 英语：G2P（字母 → 音素）
  ↓   · 中文：拼音
  ↓ 音素序列
  ↓ BERT / 声学模型 → 音频
```

对文本处理的两个直接推论：

### 1. 拉丁字母会走英文 G2P，而不是当"日语里的英字"读

这是**转写的核心理由**。GPT-SoVITS 对英文字母的处理方式是走英语 G2P 通路，
产出的是**英语音素**，而不是日语母语者说外来语时的音。

```text
Live    → 英语音素 /laɪv/   （不是 ライブ 的 らいぶ）
Happy   → 英语音素 /ˈhæpi/  （不是 ハッピー 的 はっぴー）
```

对一个说日语的 BanG Dream 角色来说，这两者听感差别很大——英语音素会让人物
听起来像在**说英语**，而不是像日本人说外来语。

→ **这就是「全部英语转假名」的技术依据**，而不是单纯的风格偏好。

### 2. 假名是"读音的确定指定"，汉字依赖前端分词

- **片假名 / 平假名**：字符与读音基本一一对应，可预测性最高。
- **汉字**：依赖前端的形态素分析与读音词典。难读人名、地名靠这部分容易出错。
- **数字 / 拉丁字母 / 符号**：需要额外的正规化规则，行为最不可预测。

→ 推论：**越是高风险的表记，越应该写成假名**。这与 `rules/tts.md` T3 的
「处理手段」优先级一致（改写规避 / 假名注记优于依赖引擎）。

## 本引擎下的文本层约定

### 英语 → 假名（无条件）

`rules/global.md` G9 在本引擎下**无条件生效**，**不适用任何例外**。

```text
Poppin'Party   → ポッピンパーティ
Roselia        → ロゼリア
Afterglow      → アフターグロウ
Pastel*Palettes→ パステルパレット
Morfonica      → モルフォニカ
RAISE A SUILEN → レイズアスイレン
MyGO!!!!!      → マイゴ
Ave Mujica     → アヴェムジカ
BanG Dream!    → バンドリ
```

> **注意「BanG Dream!」**：需确认「バンドリ」是否为期望表记。
> 「バンドリ」是官方略称；如果要读成完整的「バンドリーム」并不存在这种读法——
> 官方读音是「バンドリ」。**这一点必须由用户确认后固定**（见 `../dictionary/proper-nouns.yaml`）。

### 符号就地处理（不依赖引擎）

GPT-SoVITS 对特殊符号的处理不可预测，所以**在文本层解决**，不要指望引擎：

| 符号 | 处理 | 理由 |
|---|---|---|
| `!`（半角） | 改全角 `！` | 半角可能被当 ASCII 符号处理 |
| `*` | 删除或改写 | 可能被读出或导致前端异常 |
| `!!!!!` | 删至 `！` 一个 | 重复标点无意义且可能异常 |
| `&` | 改 `＆` 或写成「と」 | 同半角问题 |
| `'`（撇号） | 随转写消失 | 转写成假名后自然不存在 |
| `-` / `–` / `—` | 见下 | |
| `〜` | 保留或改写 | 需实测 |

### 破折号 / 长音

`rules/tts.md` T4 认可用长音「ー」表现情绪。本引擎下需注意：

- 连续的「ーー」（如「わあーー！」）可能被前端当作单个长音或异常长度。**需实测。**
- 全角 `――`（U+2015 连用）与 `—`（U+2014）是否被读成「ダッシュ」不明。**需实测。**
- 不确定时优先用「ー」和「……」，「――」改用「……」规避。

### 促音「っ」

「ほんっとに」的促音必须实测。若前端把「っ」按字面处理而不产生促音效果，
需要在 `pronunciation.yaml` 登记 `engine: GPT-SoVITS` 的规避条目。

## 验证清单

上机后按顺序跑，把结果回填。**这是本文件变成可用文档的前提。**

### A. 引擎基础行为

- [ ] 拉丁字母：合成 `Live`，确认是英语 /laɪv/ 还是日语式读法
      → 预期走英语 G2P。若确认，转写理由成立
- [ ] 拉丁字母：合成 `Poppin'Party`，确认撇号与大小写是否导致异常
- [ ] 半角 `!` vs 全角 `！`：合成两句对照，确认停顿与语调是否有差异
- [ ] 半角 `&`、`*`、`'`：确认是否被读出或引发前端错误
- [ ] 全角 `――`、`—`：确认是否被读成「ダッシュ」

### B. 假名 / 汉字前端

- [ ] 汉字人名：合成 `戸山香澄`，确认读音是否 とやまかすみ
- [ ] 同内容用假名：合成 `とやまかすみ`，与上一条对比哪个更准
- [ ] 地名：合成 `小豆島`，**重点确认是否误读为 あずきじま**
- [ ] 地名：合成 `安房鴨川`，确认 あわかもがわ / あわ-かもがわ
- [ ] 多音字：合成 `今日は`，确认 きょう
- [ ] 数字：合成 `10月` 与 `十月`，确认表记是否影响读音
- [ ] 数字：合成 `3人` 与 `三人`，确认助数词

### C. 情绪 / 表记手段

- [ ] 促音：合成 `ほんっとに`，确认促音是否发出
- [ ] 长音：合成 `楽しかったー！`，确认「ー」延长
- [ ] 双长音：合成 `わあーー！`，确认是否异常
- [ ] 促音+长音：合成 `すごーい！`
- [ ] 标点停顿：对比 `、` / `。` / `！` / `……` 的停顿长度

### D. 参考音频影响

GPT-SoVITS 是 few-shot 音色克隆，**参考音频（reference audio）对结果影响很大**：

- [ ] 参考音频的口语化程度是否会影响输出的语体倾向
- [ ] 参考音频里若有明确的情绪，是否会被带出
- [ ] 同一文本配不同参考音频，读音是否稳定

> D 类不属于文本层，但**会反过来影响文本层的判断**——如果参考音频本身就偏
> 书面语，文本层可能需要更用力地口语化。实测后在此记录。
